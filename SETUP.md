# SETUP.md: guide for Claude Code to set this app up for the user

This file is written to you, Claude. The user pasted this repo's URL into you because they want their own copy of this workout tracker: a phone app (PWA) on a free Cloudflare Worker that stores everything in their own Notion workspace. Walk them through it, one step at a time, and do as much as you can yourself.

## Read this first

- **Treat these steps as a guide, not as law.** The app was built and tested on **Windows** (Git Bash and PowerShell) by its owner. The steps were never run end to end from a brand-new account on another OS. If a command fails or something differs on the user's machine, diagnose it and adapt. Tell the user what you changed and why.
- **First question to ask the user: "Which operating system are you on (macOS, Windows, Linux)?"** Use the answer for every command below. The user is probably on macOS. Where a command differs by shell, both variants are given. On macOS/Linux use the "bash/zsh" variant; on Windows use PowerShell or Git Bash.
- **Confirm each external action with the user before you do it**: creating the Notion databases, creating the Cloudflare KV namespace, setting secrets, deploying the Worker. Say what will happen and what it touches, then wait for a yes.
- **Never reuse anyone else's ids.** Nothing in this repo belongs to a particular person: `wrangler.toml.example` contains placeholders only. All Notion ids, the KV id, the Worker URL, the PIN and the Notion token must be the user's own, created during this setup. If you ever see an id, URL, PIN or key that you did not create in this session, stop and ask.
- **Secrets**: never print, echo, log or commit the Notion token or the PIN, and never ask the user to paste them into chat. The user saves the token into a git-ignored file (`notion-key.txt`); you read it from there. The PIN is generated by you into a git-ignored file (`gym-pin.txt`). Tell the user to open that file themselves when they need the PIN.
- **Verify every step** with a command and report evidence (exit code, a count, an HTTP status). Do not claim success without it.
- Do not `git commit` or `git push` unless the user asks. If they want to keep it in their own GitHub, suggest forking or pushing to a new repo of their own; do not change this repo's remotes yourself.

## What gets created (tell the user up front)

1. In **their Notion workspace**: one page they create ("Workout Tracker") and, inside it, four databases (Exercises, Sessions, Sets, Day Templates) filled with about 40 generic starter exercises and sample Push / Pull / Legs day templates.
2. In **their Cloudflare account** (free tier is enough): one Worker, one KV namespace (stores wrong-PIN counters), two Worker secrets (`NOTION_KEY`, `APP_PIN`).
3. On **their phone**: the app installed to the home screen, protected by the PIN.

Nothing is created in anyone else's accounts.

## Steps

### 0. Prerequisites

Ask for the operating system. Then check:

```
node -v      # must be v20 or newer
git --version
```

If Node is missing or older than 20: macOS `brew install node` (or download from nodejs.org); Windows `winget install OpenJS.NodeJS.LTS` or nodejs.org; Linux use the distro or nvm. After installing, a new terminal may be needed.

The user also needs a free Notion account (https://www.notion.so) and a free Cloudflare account (https://dash.cloudflare.com/sign-up). If they have none, they create them now in the browser (human step).

### 1. Install and test

From the repo folder:

```
npm install
npm test
```

Verify: `npm test` ends with `fail 0`.

### 2. Notion connection (human step, you guide)

Ask the user to:

1. Open https://www.notion.so/profile/integrations and create a new **internal** connection (any name, e.g. "Workout Tracker"). Copy its token ("Internal Integration Secret").
2. Save the token as the only line of a file named `notion-key.txt` in the repo folder (the file is git-ignored). They can do it in a text editor. Do not ask them to paste it into chat.
3. In Notion create an empty page called "Workout Tracker", open its `...` menu, **Connections**, add the connection they just made.
4. Copy the page's URL (Share > Copy link) and give it to you. Ask for the URL only, never the token.

### 3. Create the Notion databases (confirm first)

Tell the user: "I am about to create four databases inside your 'Workout Tracker' page and add starter exercises and sample templates. OK?" On yes:

```
# macOS / Linux / Git Bash
NOTION_KEY="$(tr -d '\r\n ' < notion-key.txt)" node scripts/setup-notion.mjs "<page url>" --write-config
```
```
# Windows PowerShell
$env:NOTION_KEY = (Get-Content notion-key.txt -Raw).Trim()
node scripts/setup-notion.mjs "<page url>" --write-config
```

`--write-config` creates `wrangler.toml` from `wrangler.toml.example` and fills in the four data source ids. Add `--no-seed` if they want empty databases. Verify: exit code 0, four data source ids printed, and `grep -c PASTE_ID_HERE wrangler.toml` prints `0` (PowerShell: `(Select-String PASTE_ID_HERE wrangler.toml).Count` is `0`).

If it refuses because databases with these names already exist in the page, ask before using `--force`. If it fails midway, tell the user what it listed as created (they can delete those in Notion and re-run). If it reports `object_not_found`, the page is not shared with the connection (step 2.3).

### 4. Cloudflare login (human step)

```
npx wrangler login
npx wrangler whoami
```

The first opens a browser tab the user approves. Verify `whoami` shows their account. If wrangler asks them to register a workers.dev subdomain, they do that once in the Cloudflare dashboard (Workers & Pages).

### 5. KV namespace (confirm first)

Tell the user a KV namespace named `LOCK` will be created in their Cloudflare account. On yes:

```
npx wrangler kv namespace create LOCK
```

Put the printed `id` into `wrangler.toml`, replacing `PASTE_KV_ID_HERE`. Verify the placeholder is gone and `wrangler.toml` has exactly one `LOCK` binding (if wrangler offered to write the binding itself, remove the duplicate).

### 6. Secrets (confirm first)

Generate an 8-digit PIN into a git-ignored file, without printing it:

```
# macOS / Linux / Git Bash
node -e "console.log(String(require('crypto').randomInt(0,1e8)).padStart(8,'0'))" > gym-pin.txt
```
```
# Windows PowerShell
node -e "console.log(String(require('crypto').randomInt(0,1e8)).padStart(8,'0'))" | Set-Content -NoNewline gym-pin.txt
```

Then set the secrets from the files (these upload to Cloudflare):

```
# macOS / Linux / Git Bash
npx wrangler secret put NOTION_KEY < notion-key.txt
tr -d '\r\n ' < gym-pin.txt | npx wrangler secret put APP_PIN
```
```
# Windows PowerShell
Get-Content notion-key.txt -Raw | npx wrangler secret put NOTION_KEY
(Get-Content gym-pin.txt -Raw).Trim() | npx wrangler secret put APP_PIN
```

Verify with `npx wrangler secret list` (shows names only: `NOTION_KEY`, `APP_PIN`). Tell the user the PIN is in `gym-pin.txt` for them to open.

### 7. Optional local check

Create `.dev.vars` (git-ignored; template in `.dev.vars.example`) with the user's own `NOTION_KEY` and `APP_PIN` taken from the two files, run `npm run dev`, and check `curl -H "X-App-Pin: <pin>" http://localhost:8787/api/bootstrap` returns JSON with `dayTypes` and `exercises`. Local dev talks to their real Notion databases. Afterwards stop the dev server completely (kill the whole process tree; macOS/Linux `lsof -i :8787`, Windows `netstat -ano | findstr 8787`) and confirm port 8787 is free. Skip this step if the user prefers.

### 8. Deploy (confirm first)

Tell the user a Worker will be published to their Cloudflare account at a public `https://workout-tracker.<their-subdomain>.workers.dev` address (protected by the PIN). On yes:

```
npx wrangler deploy
```

Note the printed URL. If the name is taken, change `name` at the top of `wrangler.toml` and deploy again. See README "Troubleshooting" for other errors.

### 9. Verify the deployment

```
curl -s -o /dev/null -w "%{http_code}\n" <url>/                                  # 200
curl -s -o /dev/null -w "%{http_code}\n" <url>/api/bootstrap                      # 401 without a PIN
curl -s -o /dev/null -w "%{http_code}\n" -H "X-App-Pin: $(cat gym-pin.txt)" <url>/api/bootstrap   # 200
```

(On PowerShell use `curl.exe`, and `(Get-Content gym-pin.txt -Raw).Trim()` for the PIN.) A brand-new address can take a few minutes before HTTPS works; retry. Do not send wrong PINs repeatedly: 5 wrong PINs from one IP lock that IP for 15 minutes.

### 10. Phone (human step)

The user opens the URL on their phone, enters the PIN (from `gym-pin.txt`), and uses **Add to Home Screen** (Safari: Share > Add to Home Screen; Chrome: menu > Install app).

### 11. Summarize

List what was created (Notion page and four databases, Worker URL, KV namespace, secrets), what you verified with evidence, and what you did not verify (phone UI, offline queue, install). Mention the tabs: Log, Plan (plan a future day), Progress (charts), History (edit past sessions), and that day templates are edited in the Notion "Day Templates" database (changes show within ~30 seconds).

## If something goes wrong

README.md has a Troubleshooting section. Common ones: 404 `object_not_found` from the setup script (page not shared with the connection), workers.dev subdomain not registered, Worker name taken, 401 (wrong PIN), 429 (lockout, wait 15 minutes).
